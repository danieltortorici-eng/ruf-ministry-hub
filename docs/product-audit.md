# Calm OS Product Audit

Audit date: 2026-07-15

## Inventory and disposition

| Area | Before | Disposition | Calm OS outcome |
| --- | --- | --- | --- |
| Today | Up to eight competing groups: backup, coach, Start Here, Autopilot, shortcuts, capture, loose items, people, tasks | Rebuild | `Next thing to do`, inline Quick Capture, and `After that` only; one compact critical alert when required. |
| Start Here + Autopilot | Two highlighted explanations of the next action | Merge | One recommendation engine and one highlighted action. |
| Quick Grab | Text plus category and urgency chips, queue, recent list | Rebuild | Capture raw text first; no visible record type, category, or urgency choice. |
| Quick Review + processing | Separate review queue and 23-control conversion form | Merge | One proposal and approval workflow for every capture source. |
| Profile creation actions | Four record-specific sheets save directly | Merge | One person-linked capture; proposal-first structured changes. |
| AI Review | Useful selection/edit/partial-approval engine with administrative language | Simplify | Suggested updates, review before saving, and Save approved updates. |
| People | Four stat boxes, timestamp, preferred contact, three equal actions; no list thumbnail | Simplify | Fixed thumbnail/initials, name, two-part identity, care level, contextual follow-up; whole card opens. |
| Profile | Field grid, 11 equal actions, unlimited duplicate history | Rebuild | Essential header, Right Now, unified capture, Brief Me, Follow Up, collapsed details, bounded previews. |
| Brief Me | Privacy-safe grounding, but requires gate and leaving profile | Simplify | Immediate grounded local summary with low-information and sensitivity states. |
| Follow Up | Safe variants exist behind gate and AI Review | Simplify | Immediate useful draft, quiet variants, copy only; never send or complete automatically. |
| Prayer | Primary ministry destination with dense filters/actions | Keep/simplify | Retain primary navigation; move administration under disclosure. |
| Search | Mobile primary tab, topbar action, and People search | Move | People search is primary; broader search is contextual/More. |
| AI Review | Primary mobile destination | Move | Contextual from Capture and More. |
| 15 Minutes + Weekly Reset | Useful secondary workflows | Move | More. |
| Coach, donor builder, data janitor, duplicates, readiness, manual | Administrative tools compete with care | Move/hide | Group under progressive More subsections; no worker/agent language in normal UI. |
| Settings/Data | 16 visible sections, 52 controls, 31 buttons, 13 primary buttons | Rebuild | Grouped and collapsed Ministry tools, Privacy, Data safety, and App settings. |
| Timestamps | Created/Updated metadata repeated on normal cards | Hide | Deliberate details/audit only. |
| Preferred contact | Card, profile, form, search, briefings, demo, new records | Dormant | Preserve old data; remove every active use and new default. |

## Delete-first targets

- Remove normal Today dashboard sections, duplicate Start Here/Autopilot surfaces, primary AI/administration navigation, category/urgency capture controls, profile action cluster, top field grid, normal Created/Updated lines, and preferred-contact behavior.
- Merge all raw input into `quickGrabs` as the existing canonical capture collection.
- Reuse the proposal engine, storage keys, backup envelope, privacy gates, local record constructors, service worker, and sheet shell after safety/accessibility corrections.
- Relocate administrative features rather than deleting their data or access.

## Acceptance interpretation

Calm OS is successful when the first viewport answers one question, exposes one dominant action, stays within the attention budget, and preserves full data access through progressive disclosure. Time in the app is not a success metric; open, understand, act, and leave is.
