# Calm OS Design Principles

## Product posture

Calm OS is a quiet ministry assistant, not a database dashboard. Every primary screen answers one question and makes one action visually obvious. The interface should leave the user less overwhelmed than when it opened.

## Working principles

1. **Ministry first:** name people and acts of care before fields, types, and system states.
2. **One question per screen:** Today asks what is next; Capture asks what to remember; People asks whom to find; Profile asks what matters now; Prayer asks whom or what to pray for; More holds administration.
3. **One primary action:** a screen may expose secondary actions, but only one receives dominant color and weight.
4. **Capture before classification:** save messy input first and sort it after capture.
5. **Progressive disclosure:** essential care context precedes details, history, and administration.
6. **Recognition over recall:** photos/initials, identity lines, contextual dates, and grounded summaries reduce memory burden.
7. **Interruption recovery:** drafts, proposals, focus, and safe retry state survive a switch, refresh, suspension, or failed network call.
8. **Grounded assistance:** Right Now, Brief Me, Follow Up, and recommendations use saved evidence only. Calm OS does not invent, diagnose, rank worth, or spiritually score people.
9. **Privacy by default:** local-first storage, minimum AI context, masked previews, explicit approval, and no silent structured writes.
10. **Finish and leave:** optimize open → understand → act → return to ministry, not time in the app.

## Review questions

- What decision, reading, tap, scroll, badge, color, or repeated fact can be removed?
- Is the next action clear within three seconds at 390px?
- Does adding this feature force something lower-value behind disclosure?
- Can the interaction resume safely after interruption?
- Is every sentence grounded in saved data or plainly an empty state?
- Is the action reachable with one hand and understandable without color?
